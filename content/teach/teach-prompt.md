# Teach pass

This file is a prompt. A model runs it to rewrite the docs in this folder to Adit's level and to keep levels.md current. Run it from Claude Code opened at the repo root: `follow content/teach/teach-prompt.md`, optionally followed by `and write a doc on <topic>`.

## Instructions to the model

Work only inside content/teach/. Read levels.md first, then every doc in the folder, then content/calls/readout.md (its Misses and Dormant sections). Never edit anything outside content/teach/, and never write a line in content/calls/calls.md. Today's date is the date you run.

A doc is a markdown file in this folder other than README.md, levels.md and this file. Its first line is `Written by a model for Adit. Not Adit's words.` Its `##` headings are its topics; a topic's key is `<file stem>#<heading>`. Each doc ends with a `## Changes` section of dated one-line entries.

Levels run 1 to 5: 1 needs the foundations laid, 2 can follow with every step shown, 3 can follow a normal derivation, 4 can reproduce it, 5 can derive it cold and sees what it leaves out. A topic with no entry in levels.md starts at 3.

Marks. Adit marks a passage by appending an Obsidian comment after it: `%% lost %%` (beyond them), `%% easy %%` (too easy), or `%% forgot %%` (knew it, and it is gone), each optionally followed by a reason, as in `%% lost: where does the second term come from %%`. For each mark, in the topic it falls under:

- lost: lower the level by one; rewrite that passage from one level further back, defining every term it uses before using it, with the derivation's steps shown and the reason, if given, answered directly.
- easy: raise the level by one; compress that passage to the result and one line on where it comes from.
- forgot: lower the level by one; rewrite the passage as the shortest derivation that starts from a topic Adit holds at level 4 or 5 (a level reached earlier in this same run counts) and arrives at the result, so the hook is something they still have. If no such topic exists, start from the foundations as for lost.

Rewrite only the marked passages and what must change for them to read continuously. Remove the marks you acted on. Add one line to the doc's Changes: the date, the topic, the mark, and what moved.

The ledger. A line under Misses in readout.md whose call or settle text names a topic's heading (the heading's words, not words from the body) is evidence on that topic, recorded in levels.md with its id, verb and the date shown in readout.md. A matching line under Dormant is recorded the same way with the word dormant. Ledger evidence never moves a level and never triggers a rewrite; it only appears in the evidence list and counts toward the forgets flag as one forgot.

levels.md. Regenerate it whole every run. First line: `Generated by a model on <date>. Not Adit's words. Delete freely.` Then one line per topic, sorted by file then heading:

    <file stem>#<heading> | level <n> | foundations | forgets | <evidence, newest first: date mark, or date c<N> verb> | last touched <date>

foundations is set when the topic has never been marked lost and has been marked easy twice or is at level 5; forgets when its evidence holds two forgots (marks or dormant ledger lines), or easy and then lost. This is the only definition of the flags. Leave the slot empty when the flag is off. last touched is the date the topic's passage was last written or rewritten. After the topic lines, two short lists: `Foundations:` the topics with that flag, and `Difficult or forgotten:` the topics at level 2 or below or with the forgets flag. Nothing else.

Writing a new doc, when asked for one on a topic. Choose the level from levels.md where the topic or its parts already appear, else 3. Write it as a derivation that starts from what Adit holds and arrives at results they can use, with jargon defined at first use, ISO dates, no bold lead phrases, no emoji, headings at most `##`. Give it the first line above, topics as `##` headings, and an empty Changes section. Add its topics to levels.md.

Rules that override everything above. A doc explains a theory and derives its results; it never says which model Adit should choose for a live project, what to assume in one, or how much fidelity it needs. If a request asks for that, write the theory and add one line saying the choice is a call for content/calls/calls.md. Never remove a mark you did not act on. Never touch a passage that was not marked unless continuity requires it. Keep every doc readable with nothing installed.
