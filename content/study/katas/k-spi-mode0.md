> [!kata] SPI mode 0 controller, one byte, `sclk` period of four clocks
> Exchange one byte with a peripheral in [SPI mode 0](../basics/dd-serial.md#^spi-modes): `sclk` idles low, both sides sample on its rising edges and change their data on its falling edges. One `sclk` period is four `clk` cycles. Outputs are checked right after every rising edge of `clk`.
>
> - Idle: `cs_n` = 1, `sclk` = 0, `mosi` = 0, `busy` = 0, `done` = 0.
> - A rising edge with `start` high, while `busy` is 0 and `rst` is low, accepts `tx_byte`. Call it edge 0. Right after edge $e$:
>   - $e$ = 0 to 33: `cs_n` = 0 and `busy` = 1;
>   - `sclk` = 1 when $e \le 31$ and $e \bmod 4$ is 2 or 3, and 0 otherwise (eight pulses, rising right after edges 2, 6, ..., 30);
>   - $e$ = 0 to 33: `mosi` = `tx_byte[7 - i]` with $i = \min(\lfloor e/4 \rfloor, 7)$, most significant bit first;
>   - $e$ = 34: `cs_n` = 1, `busy` = 0, `mosi` = 0, and `done` = 1 for this one cycle.
> - Bit $7-i$ of the received byte is `miso` at edge $4i+2$, the edge that raises `sclk` for the $(i+1)$-th time. The peripheral guarantees `miso` only at those edges.
> - `rx_byte` shows the received byte from edge 34 on and holds until the next `done`. It never shows a partly received byte.
> - A `start` at an edge where `busy` was 1 before the edge is ignored (that includes edge 34). Only `tx_byte` at edge 0 matters.
> - `rst` (synchronous, active high) aborts any transfer and returns to idle with `rx_byte` = `8'h00`. It wins over `start`.
>
> Example: sending `8'h96` to a peripheral that answers `8'h3c` ends with `done` = 1 and `rx_byte` = `8'h3c` right after edge 34.
