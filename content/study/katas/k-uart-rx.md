> [!kata] UART receiver, 8N1, eight clocks per bit
> Receive 8N1 frames ([the frame](../basics/dd-serial.md#^uart-frame)) from `rx`, which idles at 1 and is already synchronous to `clk`. The nominal bit time is `CLKS_PER_BIT` = 8 clock cycles; the far end's clock is not exact, so a bit on `rx` may last 7 or 9 cycles, with the drift over one frame within two cycles. Outputs are checked right after every rising edge.
>
> - After reset the receiver is **hunting**. An edge at which it is hunting and `rx` is 0 is the frame's edge $s$. Counting from $s$:
>   - if `rx` is 1 at edge $s+4$, the low was a glitch: no output, and hunting resumes from edge $s+5$;
>   - otherwise data bit $k$ (for $k$ = 0 to 7, least significant first) is the value of `rx` at edge $s + 4 + 8(k+1)$, and the stop bit is `rx` at edge $s+76$.
> - Right after edge $s+76$: if the stop bit is 1, `valid` = 1 and `data` is the received byte; if it is 0, `frame_err` = 1 and `data` keeps its old value. Hunting resumes from edge $s+77$.
> - `valid` and `frame_err` are 0 after every other edge. `data` changes only when `valid` is 1 (and on reset).
> - `rst` (synchronous, active high) returns to hunting and sets `data` = `8'h00`, `valid` = 0, `frame_err` = 0. It wins over everything, including a low `rx`.
>
> Example: `8'h3a` sent with exactly 8 cycles per bit, whose start bit is first seen at edge $s$, gives `valid` = 1 and `data` = `8'h3a` right after edge $s+76$.
^spec

```ports
input clk
input rst
input rx
output [7:0] data
output valid
output frame_err
```
